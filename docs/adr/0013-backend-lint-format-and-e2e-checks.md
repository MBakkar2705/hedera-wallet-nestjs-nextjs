# ADR 0013: Backend lint, format and end-to-end checks

- Status: Accepted
- Date: 2026-10-11

## Context

Before this decision, the backend had a lint configuration and an end-to-end test that could not run (`docs/backend-evolutions.md`, item 11):

- `backend/eslint.config.mjs` imported packages that `backend/package.json` did not declare, and there was no lint script. Once the packages were installed, the lint reported 1,632 problems: 1,582 formatting errors raised by Prettier run as an ESLint rule, 49 other errors and 1 warning.
- `backend/test/app.e2e-spec.ts` imported `supertest`, which was not declared. It expected the text `Hello World!` while the application answers `Welcome to Hedera Wallet API by M. Bakkar!`. It starts the whole `AppModule`, which needs four environment variables (`OPERATOR_ID`, `OPERATOR_KEY`, `HEDERA_ACCOUNT_ID`, `HEDERA_PRIVATE_KEY`) and opens `hedera-wallet.db`.
- Once the e2e test ran, Jest printed "did not exit one second after the test run has completed" and the terminal stayed blocked. In `@hashgraph/sdk` 2.68.0, `Client.forTestnet()` schedules a network update in 24 hours with a `setTimeout` that is not unreferenced, and only `client.close()` cancels it. The application creates three clients (`HederaModule`, `AccountsService`, `TokensService`) and never closed them.

The criteria used to make the checks usable:

- **Signal:** the lint reports problems in the code, not in its layout.
- **Formatting checked:** the layout is checked by a tool, apart from the lint.
- **No secrets:** the checks must run in the CI without the Hedera credentials (ADR 0006).
- **Tests that end:** a test run finishes by itself.
- **Small change in the application:** this decision is about tooling, so the application code is touched only where a check needs it.

## Decision

1. **ESLint for quality, Prettier on its own.** The Prettier rule is removed from ESLint, `eslint-config-prettier` turns off the ESLint rules that conflict with Prettier, and `backend/package.json` has three scripts: `lint`, `format` and `format:check`. `backend/.prettierrc` sets `singleQuote`, `trailingComma: "all"` and `endOfLine: "auto"`. The 27 files that Prettier changed were reformatted in a commit of their own.
2. **Fixes for the other lint problems.**
   - `void bootstrap();` in `main.ts`, and an unused import removed from `tokens.service.spec.ts`.
   - Two `eslint-disable-next-line @typescript-eslint/no-base-to-string` comments in `accounts.service.ts`, with the reason. `PrivateKey` and `PublicKey` define `toString()` at runtime, but the SDK type files declare only `toStringDer()` and `toStringRaw()`. The code is unchanged.
   - A block in `eslint.config.mjs` that turns off `no-unsafe-assignment`, `no-unsafe-call`, `no-unsafe-member-access`, `no-unsafe-return` and `no-require-imports` for `src/**/*.spec.ts`. The unit tests mock the SDK with `jest.mock` and read it back with `require`, which gives the type `any`. The folder `test/` is not in this block.
3. **An end-to-end test that runs.** `supertest` and `@types/supertest` are declared, `pnpm --filter backend test:e2e` runs the test, the expected text is the one the application returns, and the test sets the four variables itself with throwaway values (a key generated by `PrivateKey.generateED25519()` at each run). The application is closed after each test.
4. **The Hedera clients are closed when the application closes.** `AccountsService` and `TokensService` implement `OnModuleDestroy`, and `HederaModule` closes the client it provides. The client that `TopicsService` receives is the one of `HederaModule`.
5. **The CI runs the three checks** after the unit tests: lint, format check and end-to-end test (see the note of 2026-10-11 in ADR 0006).

## Alternatives considered

- **Prettier as an ESLint rule (the configuration before this decision).** Rejected on the signal criterion. The documentation of Prettier ("Integrating with Linters") calls it "generally not recommended" and prefers `prettier --check` apart from the linter, because the editor fills with red underlines and the lint is slower.
- **No Prettier.** Rejected: the 1,582 formatting errors showed that the code was not formatted in a consistent way.
- **Typed mocks in the unit tests (`jest.mocked`) instead of turning rules off.** Rejected for this lot. The three test files contain 9 `require(` calls, which account for 39 of the lint errors, and replacing them would mean rewriting the way each test sets its mock, with a risk of changing what the tests check. It remains an improvement to consider.
- **`toStringDer()` instead of `toString()` in `accounts.service.ts`.** Not chosen: for `PublicKey`, `toString()` delegates to the inner key, and it was not checked that the result is identical to `toStringDer()`. The behavior of the API stays as it was.
- **A separate database for the e2e test through a `DATABASE_PATH` variable.** Postponed to the configuration lot, because it changes `app.module.ts`. The e2e test uses the local `hedera-wallet.db`.
- **`--forceExit` in the `test:e2e` script.** Rejected: it hides the symptom and leaves the clients open. Doing nothing and stopping the test with Ctrl+C was rejected too.

## Consequences

- The backend has the same kind of checks as the frontend: `pnpm --filter backend lint`, `format:check` and `test:e2e`, run by the CI on every push and pull request.
- A change of formatting shows up as a failure of `format:check`, not as a lint error. `pnpm --filter backend format` fixes it.
- The unit tests under `src/` are exempt from five type-safety rules. The e2e test in `test/` is not, and the lint passes on it.
- The two `eslint-disable-next-line` comments depend on the SDK types. If a later version of the SDK declares `toString()`, they are no longer needed.
- The e2e test opens `backend/hedera-wallet.db` when the application starts, on the machine of the author and on the CI runner. The test only calls `GET /`.
- The four environment variables are still required (item 10 of `docs/backend-evolutions.md`: two pairs for one account), so the test sets four values.
- The application code changed in this tooling lot in three places: `main.ts` (`void`), the two services and `HederaModule` (closing the clients).

## Verification

### Proven

- In `@hashgraph/sdk` 2.68.0 (read in `node_modules`): the 24-hour `setTimeout` of the network update has no `unref`, and `client.close()` cancels it. `PrivateKey` and `PublicKey` define `toString()`, and the `.d.ts` files declare `toStringDer()` and `toStringRaw()` only.
- `pnpm --filter backend lint` reports no problem, `pnpm --filter backend format:check` passes, and `pnpm test` runs 4 suites and 20 tests (reported by the author).
- `pnpm --filter backend test:e2e` passes, and after the clients are closed the terminal is given back without the "did not exit" message (reported by the author).
- The CI, with the three steps added, was green on commit `24ade28` and on the commits after it (reported by the author). This includes the e2e test with the native `sqlite3` module on the runner.
- The Docker image built from this branch started and served Swagger on port 3000 (observed by the author, ADR 0005).

### Not proven

- That the 24-hour timers were the only open handles of the e2e test: `--detectOpenHandles` reported none, and the proof is only that the test ends once the clients are closed.
- The cause of the Jest warning seen once on the unit tests (item 12). It was not seen again in at least five runs of this lot (reported by the author), and nothing in this decision addresses it.
- That `onModuleDestroy` also runs when the process receives a stop signal (that depends on `enableShutdownHooks()`, which was not checked).
- That the CI turns red when the lint, the format check or the e2e test fails: no failure was provoked on purpose.
